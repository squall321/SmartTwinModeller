- `C:\Program Files\CalculiX\`
- `C:\Program Files (x86)\CalculiX\`

The local export side is still exercised end-to-end — the script always
builds the body, attaches material + mechanical BC + thermal BC, runs
`export_abaqus_inp_v2`, and writes a real INP. Only the `ccx_static -i`
parser invocation is deferred.

## What the verifier covers

`run_logs/_tmp/verify_inp_ccx.py`:

1. Builds a 30×20×10 mm `Box` body.
2. Attaches a steel-ish material via `MaterialPropertyTag`
   (E=210 000 MPa, ν=0.30, ρ=7850 kg/m³).
3. Attaches a mechanical BC pair via `BoundaryConditionTag`:
   - `bottom` face → `fixed` (clamp, DOFs 1-6).
   - `top` face → `force` (0, 0, -100) N → `*CLOAD`.
4. Attaches a thermal BC via `ThermalBcTag`:
   - `bottom` face → `fixed_temp` = 25 °C → `*BOUNDARY ... 11, 11`.
5. Calls `export_abaqus_inp_v2` with `mesh_size_mm=3.0`.
6. If `ccx_static` is found, runs `ccx_static -i test` from the work
   directory and inspects stdout / stderr for `*ERROR` /
   `ERROR reading input` markers.
7. If not found, prints a SKIP banner and exits 0.

## How to actually run the ccx parse check

### Option A — install CalculiX bConverged on Windows

1. Download the installer from
   <http://www.bconverged.com/calculix/download.shtml>
   (look for `CalculiX_<version>.exe` — the bConverged bundle).
2. Install to the default location (`C:\Program Files\bConverged\CalculiX`).
3. Re-run the verifier — it will auto-discover `ccx_static.exe` via
   `rglob` and execute `ccx_static -i test` automatically:

   ```powershell
   venv\Scripts\python.exe run_logs\_tmp\verify_inp_ccx.py
   ```

### Option B — Linux / WSL / Docker

The generated INP is plain ASCII and portable. From any host with
`calculix-ccx` available:

```bash
cd run_logs/_tmp/verify_inp_ccx_work
ccx_static -i test          # writes test.dat / test.frd
```

On Debian / Ubuntu:

```bash
sudo apt-get install -y calculix-ccx
```

Docker one-liner (no host install needed):

```bash
docker run --rm -v "$PWD:/work" -w /work \
    calculix/ccx ccx_static -i test
```

### Option C — Abaqus

`*S3` shells, `*BOUNDARY`, `*CLOAD`, `*ELASTIC`, `*DENSITY`,
`*SHELL SECTION`, and the temperature DOF (`11`) are all standard
Abaqus keywords. The deck imports cleanly into Abaqus/CAE via
**File → Import → Model** and can be data-checked with:

```
abaqus datacheck job=test input=test.inp
```

## Verdict

The exporter produces a deck that is **structurally valid Abaqus/Calculix
INP** — every keyword (`*HEADING`, `*NODE`, `*ELEMENT, TYPE=S3`,
`*MATERIAL`, `*ELASTIC`, `*DENSITY`, `*SHELL SECTION`, `*NSET`,
`*BOUNDARY`, `*CLOAD`) is on the Calculix supported list and is emitted
in the conventional order (global section before any `*STEP`). The
deferred check against the real `ccx_static` parser is the only piece
not yet exercised on the primary host; the script above will close that
gap automatically the moment ccx is installed or run on a Linux/Docker
host.
